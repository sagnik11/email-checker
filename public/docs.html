01Overview

A privacy-preserving alternative to ZeroBounce / NeverBounce. Runs on your own infrastructure, never sends mail, and exposes one clean HTTP API.

Each address goes through a five-stage pipeline. The result is a single flat JSON object — every field at the top level next to is_reachable, no nested syntax / mx / smtp / misc / debug sub-objects.

01
Syntax
RFC 5321/5322 + Levenshtein typo suggestions
02
Misc
disposable / role / B2C / Gravatar / HIBP
03
MX
DNS lookup, priority sort
04
SMTP
EHLO → MAIL FROM → RCPT TO + catch-all probe
05
Score
safe / risky / invalid / unknown

Verdicts

safe mailbox exists and looks deliverable. risky deliverable but flagged (disposable, role, catch-all, full inbox). invalid syntax / domain / mailbox failure. unknown network or provider issue — try again later.

02Quickstart

Run it locally

git clone https://github.com/sagnik11/email-checker.git
cd email-checker
npm install
npm run dev
# server now listening on http://127.0.0.1:8080

Validate an address

curl -X POST http://127.0.0.1:8080/v1/check_email \
  -H 'content-type: application/json' \
  -d '{"to_email":"someone@gmail.com"}'
const res = await fetch("http://127.0.0.1:8080/v1/check_email", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ to_email: "someone@gmail.com" }),
});
const data = await res.json();
console.log(data.is_reachable); // "safe" | "risky" | "invalid" | "unknown"
import requests

resp = requests.post(
    "http://127.0.0.1:8080/v1/check_email",
    json={"to_email": "someone@gmail.com"},
    timeout=30,
)
print(resp.json()["is_reachable"])

Submit a bulk job

Bulk mode requires worker.enable = true, Postgres, and RabbitMQ. See Self-hosting. 

# 1. submit
curl -X POST http://127.0.0.1:8080/v1/bulk \
  -H 'content-type: application/json' \
  -H 'x-api-secret: YOUR_SECRET' \
  -d '{"input":["alice@example.com","bob@example.com"]}'
# → { "job_id": 42 }

# 2. poll progress
curl http://127.0.0.1:8080/v1/bulk/42

# 3. download results when complete
curl 'http://127.0.0.1:8080/v1/bulk/42/results?format=csv' -o results.csv

05Authentication

Send the configured secret with every protected request: 

x-api-secret: YOUR_SECRET

When header_secret is unset, all routes are open. When it's set, missing or wrong values return 400. /health, /ready, /version, and / are always unauthenticated.

Browser bypass. Set allow_browser_without_secret = true (or EMAIL_CHECKER__ALLOW_BROWSER_WITHOUT_SECRET=true) to let same-origin browser requests skip the secret check. Used by the bundled web UI so the secret never leaks to the page source. The check verifies the request's Origin / Referer host matches the server's Host.

06CORS

The default is * (all origins allowed). Restrict it for production: 

EMAIL_CHECKER__CORS__ORIGINS=https://app.example.com,https://www.app.example.com

Comma-separated string or JSON array. The server sends Access-Control-Allow-Headers: content-type, x-api-secret, authorization and a 24-hour preflight cache.

09Self-hosting

Worker mode

Async bulk processing requires a worker, RabbitMQ, and Postgres. The API and worker can run as a single inline process or as separate scaled processes.

Inline (single process)

# with worker.enable = true in backend_config.toml
email-validator serve --config ./backend_config.toml

Separate processes (recommended for production)

# API
EMAIL_CHECKER__WORKER__ENABLE=false email-validator serve

# Worker (any number of replicas)
email-validator worker --config ./backend_config.toml

Workers consume from the check_email RabbitMQ queue with prefetch = worker.rabbitmq.concurrency (default 5). Single-shot RPC checks have higher priority than bulk job tasks. Transient SMTP failures (unknown) are requeued once before being persisted.

Postgres schema

src/storage/postgres.ts auto-migrates on startup. Two tables:

  • v1_bulk_job — id, created_at, total_records.
  • v1_task_result — id, job_id, created_at, result (jsonb), extra (jsonb), error.

Aggregate progress is computed on the fly — no separate counters to keep in sync.

RabbitMQ

  • Queue: check_email (durable, priority-aware).
  • Single-shot RPC pattern uses an exclusive reply queue per request.
  • Concurrency knob: worker.rabbitmq.concurrency.

SOCKS5 proxy

When the host blocks port 25 outbound (most clouds do), route SMTP through a SOCKS5 proxy: 

{
  "to_email": "someone@example.com",
  "proxy": {
    "host": "proxy.local",
    "port": 1080,
    "username": "user",
    "password": "pass",
    "timeout_ms": 20000
  },
  "smtp_port": 25
}

Or use a different port server-side: EMAIL_CHECKER_SMTP_PORT=587.

Observability

  • Logs are JSON-lines on stdout. Set SMTP_DEBUG=true for verbose SMTP transaction logs.
  • Liveness probe: GET /health; readiness probe: GET /ready.
  • Queue depth: monitor RabbitMQ's management UI / Prometheus exporter.
  • Job status: query v1_task_result directly or poll GET /v1/bulk/{id}.

10Architecture

Verification pipeline

Orchestrated in src/checker/checkEmail.ts. Each stage may short-circuit the rest.

1. Syntax — src/checker/syntax.ts

  • RFC 5321/5322 validation via isemail.
  • Gmail / Googlemail normalization: dots stripped, +alias removed; canonical form goes into normalized_email.
  • Typo suggestions via Levenshtein distance < 3 against gmail.com, yahoo.com, outlook.com, hotmail.com, protonmail.com, icloud.com, yandex.com.

2. Misc — src/checker/misc.ts

  • Disposable: union of mailchecker + disposable-email-domains (~96k entries) + a small hardcoded override set. Domain and parent suffixes both checked.
  • Role: lowercased local part looked up in src/data/roles.txt (944 entries).
  • B2C: domain looked up in src/data/b2c.txt (~96,600 entries).
  • Gravatar: optional. MD5 hash + ?d=404 probe, 6 s timeout.
  • HIBP: optional. v3 API, 10 s timeout. Returns true / false / null on error.

3. MX — src/checker/mx.ts

  • node:dns/promises resolveMx(); sorted by priority ascending.
  • Soft DNS errors (ENODATA, ENOTFOUND, NXDOMAIN, SERVFAIL) yield accepts_mail: false and invalid.
  • Hard DNS errors throw → result becomes unknown.

4. SMTP — src/checker/smtp.ts · smtpParser.ts · provider.ts

  • Provider detected from MX hostname: gmail, yahoo, hotmailb2c, hotmailb2b, proofpoint, mimecast, everything_else.
  • TCP socket (or SOCKS5 tunnel). Port 465 → TLS automatically.
  • Sequence: 220 greeting → EHLO → MAIL FROM → optional random RCPT (catch-all probe) → real RCPT → QUIT.
  • Errors classified by smtpParser.ts: invalid mailbox, full inbox, disabled account, blacklisted IP, needs reverse DNS.
  • Retry policy: configurable retries (default 1) on unclassified errors.

5. Reachability — calculateReachable()

Evaluated in this order:

VerdictCondition
unknownAn SMTP error is present (timeout, blacklist, rDNS, …)
riskyis_disposable · is_role_account · is_catch_all · has_full_inbox
invalid!is_deliverable · !can_connect_smtp · is_disabled
safeNone of the above

Syntax failure short-circuits to invalid before the scoring matrix runs.

SMTP rules engine

src/data/rules.json stores per-domain and per-MX overrides applied in src/checker/rules.ts:

  • SkipCatchAll — skip the random-address probe (Gmail, Hotmail, Yahoo always accept random RCPTs and would otherwise look catch-all).
  • SmtpTimeout45s — bump the SMTP timeout to ≥ 45 s for slow / greylisting servers.
